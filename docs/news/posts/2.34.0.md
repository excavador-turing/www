**Firmware v2.34.0**, 21 September 2026 — the first image to carry [BMC-UI 3.32.0](../../changelog/bmc-ui.md), [BMC-UI 3.31.0](../../changelog/bmc-ui.md). Every item below is the repository's own changelog entry, taken apart; the whole entry is a click away under each one.

## Changed

- **Which module: four pills, not a drop-down.** Console, USB and Flash each opened with a list that unfolded to show four fixed entries, one already chosen.

    ??? note "The whole entry"

        The three tabs now share one picker, Node 1 to 4 side by side with the chosen one green — the same change the fleet shows, because it is one component serving both.


## Fixed

- **The fleet says which version of itself it is.** `Dockerfile.fleet` has taken a `BMC_UI_VERSION` build argument since the image existed, and the release workflow has been passing the tag into it all along — but it was set as a plain `ENV`, and **Vite only puts `VITE_`-prefixed variables into the bundle**. <small class="tp-tag">BMC-UI 3.31.0</small>

    ??? note "The whole entry"

        So the value arrived at the build and stopped there.

        The cost was not cosmetic: the deployed fleet sat **two releases behind**
        with nothing on the page able to say so. It is in the header now, beside the
        name.

- **The fleet has a footer, and a mark of its own.** It is a separate entry point built from this same tree and never renders the board's root route, so it had no logo, no version and no footer — which also meant the upstream copyright notice, which is there for a legal reason, was missing from one of the two things this repository ships. <small class="tp-tag">BMC-UI 3.31.0</small>

    ??? note "The whole entry"

        The footer is now a shared component used by both.

- **The docs link pointed at a dead host.** `turing.excavador.xyz` has not answered for some time; the documentation is at `turingpi.xyz`. <small class="tp-tag">BMC-UI 3.31.0</small>
